# aeris — Task List

Status: 2026-10-09. Implements `2026-10-09-design.md`, in small tasks. Each task is planned, agreed,
implemented, reviewed, then committed on its own.

Decisions:

- The old `aeris/` package stays untouched until the new CLI replaces it (2.5).
- `requires-python = ">=3.13"`; Vercel runs 3.14, pinned by `server/.python-version`.
- Tests that need Postgres run against a throwaway Neon branch.
- Deploys go through the Vercel CLI (`vercel deploy --prod` from `server/`), not Git integration.
- Static assets live in `server/static/`, mounted with `StaticFiles` (Vercel promotes the mount to
  its CDN). This replaces the design's top-level `public/`, which would sit outside the Vercel root.

## Findings

From the 1.2 spike (2026-10-09), production URL `https://aeris-five-silk.vercel.app`:

- **Build:** Vercel picks Python 3.14 from `.python-version` and installs dependencies with uv from
  `server/pyproject.toml`. There is no lock file in `server/`, so versions float within the `>=`
  ranges. Decide on pinning before 1.18.
- **Region:** the function runs in `iad1` (Washington, D.C.), the default; requests enter at the
  `lhr1` (London) edge. Neon is in `eu-west-2` (AWS London), so set the function region to `lhr1`
  in 1.18.
- **Latency (`/healthz`, from London):** first request after deploy 0.35 s (Vercel seems to
  pre-warm new deploys); warm requests 0.13–0.25 s, mostly the transatlantic round trip to `iad1`.
- **Cold start after 31 min idle:** 1.44 s, for a skeleton that imports only FastAPI. The real app
  adds heavier imports and Neon's own wake-up, so re-measure in 1.18 against the 1–2 s estimate in
  the design's risks section.
- **Static files:** `/static/ping.txt` is served by the CDN (`x-vercel-cache: HIT`, 0.04 s).

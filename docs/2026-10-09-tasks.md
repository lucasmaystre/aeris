# aeris — Task List

Status: 2026-10-09. Implements `2026-10-09-design.md`, in small tasks. Each task is planned, agreed,
implemented, reviewed, then committed on its own.

Decisions:

- The old `aeris/` package stayed untouched until the new CLI replaced it (removed in 2.5).
- `requires-python = ">=3.13"`; Vercel runs 3.14, pinned by `server/.python-version`.
- Tests that need Postgres run against a throwaway Neon branch. They're integration tests, marked
  `db`; `-m "not db"` runs the offline unit tests. No local Postgres required.
- Deploys go through the Vercel CLI (`vercel deploy --prod` from `server/`), not Git integration.
- Static assets live in `server/static/`, mounted with `StaticFiles` (Vercel promotes the mount to
  its CDN). This replaces the design's top-level `public/`, which would sit outside the Vercel root.
- Tags come only from `Tags: #a, #b` lines, not from inline `#tags` anywhere in the text (design §5
  updated).
- API/CLI text search filters notes in Python with `normalize`, so it matches the web search exactly.
  No `unaccent`; if the corpus grows a lot, store a normalized `search_text` column instead.
- `note_embedding.embedding` is `vector` without a fixed dimension, so switching models needs no
  migration (exact scan, no ANN index).
- Database roles: migrations run as `neondb_owner`; the server and the old CLI use `agent`
  (read/insert/update/delete only). Default privileges grant `agent` access to every table
  `neondb_owner` creates in `public`, so migrations need no `GRANT`s.
- Server config is env vars only (`.env` locally, Vercel in production); `~/.aeris.yaml` is the
  CLI's. The OpenRouter key and embedding model are server config (4.1).
- Reindexing is maintenance, so it's `aeris-admin reindex` (next to `recompute-tags`), not an API
  route or a CLI command (4.2).
- Vercel installs `server/pyproject.toml` without a lock (the workspace `uv.lock` sits at the repo
  root), so versions float within the `>=` ranges (the build log doesn't list them). Revisit if a
  deploy breaks.

## Findings

From the 1.2 spike (2026-10-09), production URL `https://aeris-five-silk.vercel.app`:

- **Build:** Vercel picks Python 3.14 from `.python-version` and installs dependencies with uv from
  `server/pyproject.toml`. There is no lock file in `server/`, so versions float within the `>=`
  ranges (decided in 1.18b: accept that for now).
- **Region:** the function runs in `iad1` (Washington, D.C.), the default; requests enter at the
  `lhr1` (London) edge. Neon is in `eu-west-2` (AWS London), so set the function region to `lhr1`
  in 1.18b.
- **Latency (`/healthz`, from London):** first request after deploy 0.35 s (Vercel seems to
  pre-warm new deploys); warm requests 0.13–0.25 s, mostly the transatlantic round trip to `iad1`.
- **Cold start after 31 min idle:** 1.44 s, for a skeleton that imports only FastAPI. The real app
  adds heavier imports and Neon's own wake-up, so re-measure in 1.18b against the 1–2 s estimate in
  the design's risks section.
- **Static files:** `/static/ping.txt` is served by the CDN (`x-vercel-cache: HIT`, 0.04 s).

From 1.17b to 1.18b (2026-10-09):

- Migrations rehearsed on the test branch (production's original table): all three applied, then
  "Up to date".
- Production migrated on 2026-10-09: 25 notes before and after; all three migrations applied. Backups:
  Neon branch `backup-2026-10-09` and `~/aeris-backup-2026-10-09.jsonl`.
- Real app in `lhr1`, measured from London: warm requests 0.05–0.10 s (was 0.13–0.25 s from
  `iad1`); `/login` after 42 min idle took 1.80 s (skeleton in 1.2: 1.44 s), without touching the
  database, whose wake-up adds to that. Acceptable for now; if it bothers, see the design's
  cold-start options (preload on hover, slimmer imports).
- `aeris` 0.5.0 released to PyPI on 2026-10-09 (GitHub release `v0.5.0`, published by the
  workflow). The installed CLI now talks to the server; `~/.aeris.yaml` holds `url` and `token`,
  and no database credentials remain on the laptop.
- The web UI showed absolute dates in UTC (as the old app did); since 3.5, `app.js` shows them in
  the viewer's timezone.

From 4.2 (2026-10-10):

- Production backfilled with `aeris-admin reindex`: 25 live notes embedded; a second run after a web
  edit embedded 0, so embedding on write works on Vercel.
